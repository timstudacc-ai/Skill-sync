# Lab Report Generation («Архітектура комп'ютера»)

Генерує звіт з лабораторної роботи у **двох форматах одночасно** — `.docx` та
`.pdf` — з одного опису вмісту. Титульний аркуш точно за зразком
**«Титульний лист лабораторних робіт.docx»** (дисципліна «Архітектура
комп'ютера»); основний текст — за загальноприйнятими правилами оформлення
НТУ «Дніпровська політехніка».

## 1. Activation (REQUIRED, критично)

Скрипти скіла працюють **лише** у виділеному віртуальному середовищі
(спільному зі скілом `lab-report`). Перед будь-яким запуском активуй його:

```bash
source ~/.venvs/lab-report/bin/activate
```

Всі модулі самі перевіряють `sys.prefix`: якщо запущено поза venv — скрипт
завершується з помилкою та підказкою про активацію. Це зроблено навмисно:
`python-docx` і `weasyprint` гарантовано є лише в цьому venv, а системний
Python їх не бачить.

## 2. Formatting rules (зашиті в рендерери)

### Титульний аркуш (за зразком docx — ВІДМІННИЙ від «Програмування»)

| Елемент | Формат |
|---|---|
| Шапка | тільки «Міністерство науки і освіти України» — центр, **жирний**; БЕЗ університету/факультету/кафедри |
| Назва | «Звіт з лабораторної роботи №N» — центр, жирний |
| Дисципліна | «З дисципліни «Архітектура комп'ютера»» — центр, жирний |
| Тема | **ВЕЛИКИМИ ЛІТЕРАМИ** (автоматично), центр, жирний |
| Виконавець | «Виконала студентка групи X» + ПІБ на окремому рядку — відступ 11.25 см праворуч, жирний |
| Викладач | «Перевірив» + «Доц. ПІБ» на одному рядку — той самий відступ, жирний |
| Низ | «м. Дніпро» / «2020 рік» — центр, жирний |

⚠️ Стать виконавця має значення: за замовчуванням «Виконала студентка
групи…». Для чоловіка передай `student_label="Виконав студент групи"` (і,
за потреби, `teacher_label="Перевірила"`).

### Основний текст

| Параметр | Значення |
|---|---|
| Папір | A4, поля 30/15/20/20 мм |
| Основний текст | Times New Roman 14 pt, інтервал 1.5 |
| Абзацний відступ | 1.25 см |
| Вирівнювання тексту | по ширині (justify) |
| Код/конфігурації | моноширинний 10 pt, ліворуч |
| Рисунки, підписи, формули, таблиці | по центру |
| Мова | українська, **тільки від третьої особи** |

Структура: `Робота №N` → тема (центр) → `Мета роботи:` → `Хід роботи`
(центр) → основний текст → `Висновки` (центр) → текст висновків.

**Стиль мови (перевіряти завжди):** заборонено «В ході роботи я зібрав…»;
правильно «В ході роботи зібрано системний блок…», «опановано…».
У висновках вживати звороти «В роботі розглянуті…», «…виконані…».

Кожен рисунок обов'язково має підпис `Рисунок N – …` та **посилання з тексту**.

## 3. Architecture (чому так)

* Один об'єкт `Report` (незалежний від формату) → `render_docx()` +
  `render_pdf()`. Джерело даних одне — розбіжності між форматами неможливі.
* DOCX — `python-docx`: нативний Word-документ для редагування/друку.
* PDF — `WeasyPrint` (HTML+CSS → PDF). Пряма конвертація DOCX→PDF у системі
  неможлива (немає LibreOffice/pandoc), тому PDF рендериться незалежно з тих
  самих даних. CSS у рендерері дзеркалить ті самі правила титульного аркуша.
* Шрифти: у DOCX прописано `Times New Roman` (є у Word користувача);
  у PDF WeasyPrint фолбекить на `Liberation Serif` — метрично ідентичний
  аналог TNR. Код: `Consolas` → `DejaVu Sans Mono`.

## 4. Workflow

### Крок 1. Зібрати дані роботи
Від користувача (або з методички/коду/фото в робочій директорії): номер
роботи, тема, мета, текст ходу роботи (від третьої особи!), висновки,
титульні дані (група, ПІБ студентки/студента, посада та ПІБ викладача, рік).
Якщо даних нема — запитай, не вигадуй.

### Крок 2. Написати скрипт генерації
Створи скрипт **у поточній робочій директорії** (наприклад `./report_lab1.py`),
НЕ у каталозі скіла чи template — папка template є лише довідковим матеріалом.
Скрипт імпортує модуль скіла через `sys.path`:

```python
import sys
sys.path.insert(0,
    "/home/tim/.agents/skills/lab-report-for-pc-arch/template")
from lab_report import (
    Report, add_paragraph, add_code, add_figure, add_formula, add_table,
    render_docx, render_pdf,
)

r = Report(
    work_number=1,
    topic="Збирання системного блоку персонального комп'ютера",
    purpose="ознайомитися з компонентами системного блоку та опанувати "
            "послідовність збирання персонального комп'ютера.",
    student_label="Виконала студентка групи",   # або "Виконав студент групи"
    student_group="124-20-2",
    student_name="Голоденко Аріадна Олексіївна",
    teacher_label="Перевірив",
    teacher_position="Доц.",
    teacher_name="Ткаченко С.М.",
    city="Дніпро",
    year=2020,
)

# Хід роботи: текст по ширині, абзацний відступ автоматично
add_paragraph(r, "В ході роботи вивчено призначення основних компонентів …")

# Код/конфігурація: моноширинний 10 pt, ліворуч
add_code(r, "CPU: Intel Core i5-10400\nRAM: 16 GB DDR4\nSSD: 512 GB")

# Рисунок: підпис автоматично "Рисунок N – …"
add_figure(r, "/path/to/photo.png", "Зібаний системний блок")

# Таблиця (за потреби): по центру, рамки, жирний заголовок
add_table(r, headers=["Компонент", "Модель"], rows=[["CPU", "i5-10400"]])

r.conclusions = ["В роботі розглянуті основні компоненти системного блоку. …"]

render_docx(r, "/home/tim/laboratorni/звіт_робота_1_ак.docx")
render_pdf(r,  "/home/tim/laboratorni/звіт_робота_1_ак.pdf")
```

### Крок 3. Запустити і перевірити
```bash
cd <робоча_директорія>
source ~/.venvs/lab-report/bin/activate
python report_lab1.py
```
Перевір PDF сторінками через `pypdf` (титульна = стор. 1, опис = стор. 2+)
та передай обидва файли користувачу на review.

## 5. API довідка

```python
Report(work_number, topic, purpose, *, variant=None,
       ministry="Міністерство науки і освіти України",
       discipline="Архітектура комп'ютера",
       student_label="Виконала студентка групи",   # стать виконавця!
       student_group, student_name,
       teacher_label="Перевірив",                  # стать викладача!
       teacher_position, teacher_name,
       city="Дніпро", year=<поточний рік>)

add_paragraph(r, text)               # абзац ходу роботи (justify, відступ)
add_code(r, text)                    # блок коду (mono 10 pt, ліворуч)
add_figure(r, image_path, caption)   # рисунок по центру + "Рисунок N – caption"
add_formula(r, text, number=None)    # формула по центру + "  (number)"
add_table(r, headers, rows)          # таблиця по центру з рамками
render_docx(r, path) / render_pdf(r, path)
```

## 6. Notes / антипатерни

* **Не малюй титульний аркуш вручну** (empty paragraphs, HTML руками) —
  рендерери вже реалізують форму зразка. Змінюй лише поля `Report`.
* **Не додавай університет/факультет/кафедру на титулку** — у зразку для цієї
  дисципліни їх немає (це НЕ форма рис. А.1 зі скіла «Програмування»).
* **Не пиши текст від першої особи** — перед додаванням абзаців перечитай їх
  і перепиши «я/ми зібрав» → «зібрано/опановано/виконано».
* Тема на титульному аркуші переводиться у ВЕРХНІЙ регістр автоматично —
  передавай тему в природному написанні.
* Фото/скріншоти збору системного блоку: білий фон, текст добре видимий.
  Якщо користувач дає лише текст без зображення — не генеруй фейковий скріншот.
* Шлях до скіла:
  `~/.agents/skills/lab-report-for-pc-arch/template/lab_report.py`.
  Сам скрипт генерації створюється **у поточній робочій директорії**; модуль
  скіла імпортується через `sys.path.insert(0, ...)` — НЕ запускай із і НЕ
  записуй файли в каталог скіла/template.
* Тестовий приклад:
  `~/.agents/skills/lab-report-for-pc-arch/template/test_report.py`.
