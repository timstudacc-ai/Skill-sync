# HTML Docs → .txt Files

Convert an HTML documentation site into a set of plain-text files. The
default deliverable (the "definition of done" pattern most users mean):

> **One .txt file per documentation section (Overview, Design, Configuration,
> …), each containing the full text of all its child pages.**

The conversion tool is `scripts/html_docs_to_txt.py` — Python 3, **stdlib
only**, no pip installs needed. Run it from the skill's `scripts/` directory.

## Workflow

### 1. Recon the site (never skip)

Fetch the index URL and determine what generator produced the docs:

- **Doxygen** (e.g. freertos.github.io/coreMQTT): the nav sidebar is rendered
  by JavaScript, so the visible HTML contains *no* nav links. The source of
  truth is `navtreedata.js` — fetch it and look for `var NAVTREE`. Tool mode
  `doxygen` handles this automatically.
- **MkDocs / Docusaurus / Sphinx / plain HTML**: real `<a href>` links exist
  in the HTML. Tool mode `crawl` does a same-host BFS over `.html` links.

Ask the user (or infer) the output layout if not stated:
- default: one .txt **per section** (child pages appended under `PAGE:` headers)
- `--flat`: everything in one `ALL_DOCS.txt`
- `--per-page`: one .txt per page

### 2. Run the tool

```bash
python3 scripts/html_docs_to_txt.py <BASE_URL> \
    --out <output_dir>          # e.g. ./docs/<LibName>_<version>
# useful flags:
#   --mode doxygen|crawl|auto   (auto is default and detects Doxygen)
#   --flat                      everything in one ALL_DOCS.txt
#   --per-page                  one .txt per page
#   --max-pages 200             crawl limit for big sites
#   --delay 0.2                 politeness delay (seconds) between fetches
#   --index-min 1500            "index page" threshold (see below)
#   --strip '^Footer text$'     extra per-line boilerplate regex (repeatable)
```

The tool prints a summary (`[mode] … N sections`, per-file writes, totals).

**Index-page expansion** (automatic): a fetched page whose extracted text is
shorter than `--index-min` (default 1500 chars) is treated as an *index page*
(e.g. Doxygen's "Functions" or "Data types" listings) and its same-site
`.html` children are pulled into the same section file. This is what makes
"full text of all its child pages" true for group-style sections. Common
Doxygen chrome pages (`files.html`, `globals.html`, `annotated.html`, …) are
excluded from expansion by name.

### 3. Verify the output (never skip)

Boilerplate leakage and missing pages are the two failure modes. Check:

```bash
# a) no leftover chrome lines in any output file (expect zero matches)
grep -ricE 'Loading|Searching|No Matches|Generated by [0-9]' <output_dir> | grep -v ':0'

# b) coverage: number of unique pages fetched vs. pages listed in the
#    site navtree / nav links (spot-check section and child page titles)
grep -c 'PAGE:' <output_dir>/*.txt ; head -30 <output_dir>/*.txt
```

If boilerplate lines remain, note the exact line, re-run with
`--strip '<regex>'`. (Version banners like `LibName v2.3.1` are
site-specific — add them with `--strip`.)

### 4. Report to the user

A short table: file name → sections/pages covered → size; plus total size,
page count, and the source URL. State any pages that failed to fetch
(reported on stderr as `WARN: fetch failed …`).

## How it works (and why it is built this way)

- **Doxygen navtree parsing** — Doxygen sites load navigation via
  `navtreedata.js`, so scraping HTML links misses the entire menu. Parsing
  `var NAVTREE` gives the exact section tree (note: cut the token stream at
  NAVTREE's closing `];` — the file also contains `NAVTREEINDEX` after it,
  which otherwise gets mis-parsed as sections). Child entries that are just
  anchors (`page.html#fragment`) are deliberately *skipped*: their text is
  already inside the parent page, and fetching them again would duplicate it.
- **Content-container detection** — text is extracted from `#doc-content`,
  `<main>`, `<article>`, or common content-class divs; if none exist, it
  falls back to `<body>` minus `nav/header/footer/aside/script/style`. Without
  this, every output file would start with menus and search boxes.
- **Non-breaking spaces are normalized FIRST** (lesson learned the hard way):
  Doxygen emits `\xa0` inside banner lines like `coreMQTT v5.0.2`, which
  silently defeats exact-match boilerplate stripping.
- **Zero-width joiners** (`\u200c`, `\u200d`) are stripped — they are invisible
  but corrupt plain-text search and diffing.
- **Tables** degrade to `cell | cell` lines — content is preserved, layout
  is not; mention this to the user if the docs are table-heavy.

## Limitations / edge cases

- JavaScript-rendered docs (React SPA with no static HTML, e.g. some GitBook
  sites) cannot be crawled — only server-rendered HTML works. If `crawl`
  finds <5 pages, suspect this and tell the user.
- SPAs that use hash routing (`docs.com/#/page`) are not supported by the
  crawler (it only follows real `.html` hrefs).
- Huge sites: raise `--max-pages`, but consider `--delay 1` to stay polite.
- Auth-protected docs are not supported (no cookie/session handling).
